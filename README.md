Пиксельный виджет активности и лимитов **Antigravity (GUI и CLI)** и **OpenAI Codex**.
Каждый экземпляр независимо выбирает сервис, тему и оформление.
Размер нового виджета по умолчанию — **256 × 288**; логотипы вписаны в одинаковую область.

![Plasma AI Status: Antigravity и Codex рядом в теме Retro Pixel](assets/preview.png)

**Один виджет — два сервиса.** Добавьте два экземпляра: один для Antigravity, второй для Codex.
У каждого свои активность, лимиты, таймеры сброса, настройки и логотип.

| Сервис | Логотип | Источник лимитов |
|---|---|---|
| **Google Antigravity (GUI + CLI)** | Пиксельный логотип Antigravity | Локальный сервер открытого приложения; запасной источник — `agy /usage`, группа Gemini Models |
| **OpenAI Codex** | Пиксельный логотип OpenAI | Официальный метод `account/rateLimits/read` через локальный `codex app-server` |

## Два виджета рядом

1. Добавьте **Plasma AI Status** на рабочий стол или панель дважды.
2. В настройках первого экземпляра откройте **Основные → Service → Antigravity (GUI + CLI)**.
3. Во втором выберите **OpenAI Codex**.

Заголовок и пиксельная иконка переключаются автоматически: `antigravity.sh` с логотипом Antigravity
или `codex.sh` с пиксельным логотипом OpenAI. В округлых темах автоматический заголовок —
`Antigravity` или `Codex`, без `.sh`. Во вкладке «Внешний вид» можно отключить
**Automatic Title** и ввести свой текст: он отображается буквально, даже если это
`codex.sh` или `antigravity.sh`. При автоматическом режиме показан текущий результат,
а поле ручного ввода скрыто. Старые стандартные заголовки остаются автоматическими;
старые пользовательские заголовки сохраняются.
В панели нажатие на иконку открывает полный виджет.

Темы, настройки и данные экземпляров независимы. Проект ранее назывался `plasma-antigravity`.
Существующие экземпляры после обновления
продолжают показывать Antigravity. Идентификатор пакета `org.kde.plasma.antigravity` сохранён,
чтобы не терять настройки и размещение виджетов.

## Данные и активность

- **Antigravity:** настоящие лимиты группы Gemini Models из локального метода
  `RetrieveUserQuotaSummary` открытого GUI-приложения; если он недоступен, используется
  `agy -p /usage --output-format json`. Для открытого GUI отдельный вход в `agy` не нужен.
  Группы Claude/GPT и Gemini 4 Argon не смешиваются с Gemini Models.
  Активность GUI, интерактивного CLI и фоновых запусков `-p` / `--print` / `--prompt`
  определяется по процессам и открытым SQLite-журналам сессий. TTY не требуется.
  Открытое приложение без активного запроса показывает «отдыхает»; если GUI и CLI
  работают одновременно, отображается наиболее активная сессия.
  Служебные запросы `/usage` не считаются работой агента. Длительные запросы
  продолжают отображаться активными, пока жива связанная сессия.
- **Codex:** официальный метод `account/rateLimits/read` через `codex app-server`.
  Используются основные лимиты `codex`, без запуска модельного запроса.
  Из `usedPercent` вычисляется остаток; время сброса берётся из `resetsAt`.
  Активность определяется по недавним локальным журналам `sessions/**/*.jsonl`
  (запрос, вызовы инструментов, завершение и отмена). Это приближённый локальный индикатор:
  облачные сессии без локального журнала он не отслеживает. Локальные сессии GUI
  поддерживаются, если приложение пишет их в тот же `CODEX_HOME`; его `app-server`
  учитывается как запущенный Codex. Служебный сервер опроса квот виджета исключается.
  Долгие запросы не становятся неактивными после трёх минут тишины, если живой Codex
  держит журнал на запись и события относятся к времени жизни этого процесса.
  Без подтверждённого владельца сохраняется защитный таймаут в три минуты.
- Два окна лимитов обычно соответствуют **5 часам** и **неделе**.
  Для Codex подписи следуют фактической длительности окна в ответе сервера.
- Квоты обновляются в фоне раз в 60 секунд, включая время, когда CLI закрыт.
  Последние успешные квоты находятся в `$XDG_STATE_HOME/plasma-agent-status`
  (по умолчанию `~/.local/state/plasma-agent-status`) и сохраняются после перезагрузки.
  Предыдущий кэш из `~/.cache/plasma-agent-status` переносится автоматически.
  Для Codex учитывается `CODEX_HOME`.
  Несколько экземпляров одного сервиса совместно используют кэш и блокировку обновления.
- Пока данных нет, показывается **«нет данных»**. При ошибке сохраняется последняя успешная квота;
  ошибка и предупреждение об устаревших данных доступны в подсказке.
  Частичный ответ сохраняет последнюю известную квоту другого окна.
  Снимок квот также хранится в настройках каждого экземпляра, чтобы восстановить
  проценты сразу при загрузке интерфейса. Автоматического сброса на 100% нет.
  Таймеры сброса пересчитываются при каждом опросе из абсолютного времени.

Для Antigravity достаточно открыть GUI-приложение и войти в аккаунт.
Если GUI закрыт, для фонового обновления нужен авторизованный `agy`.
Для Codex нужен установленный CLI с авторизацией; вход выполняется командами:

```bash
agy
codex login
```

У Codex нужна авторизация с подпиской ChatGPT, предоставляющей лимиты Codex.
Для API-key-only аккаунтов такие лимиты могут быть недоступны.
Виджет не читает и не копирует токены из файлов авторизации. Для локального сервера
Antigravity используется временный CSRF-токен из аргументов его процесса; запросы
идут только на `127.0.0.1`, без прокси и HTTP-перенаправлений. Это внутренний API
Antigravity: при несовместимом обновлении сохраняются предыдущие квоты и используется CLI.

## Установка и обновление

```bash
git clone https://github.com/skippingclass/plasma-ai-status.git
cd plasma-ai-status
./install.sh
```

Для существующей копии:

```bash
git remote set-url origin git@github.com:skippingclass/plasma-ai-status.git
git pull --ff-only
./install.sh
```

После обновления уже загруженных QML-компонентов перезапустите Plasma:

```bash
systemctl --user restart plasma-plasmashell.service
```

Добавление: ПКМ по рабочему столу → «Добавить виджеты…» → **Plasma AI Status**.

```bash
./test.sh                    # Отдельное окно Plasma
./install.sh --uninstall      # Удаление
```

Требования: KDE Plasma 6 и Python 3. Для Antigravity — открытое GUI-приложение
или `agy` в PATH оболочки Plasma; для Codex — `codex` в PATH.
Проверено чтение лимитов открытого Antigravity 2.11.0 на Linux; активность CLI/GUI
и совместная работа покрыты тестами. Другой `CODEX_HOME` или профиль приложения
автоматически не объединяется с основным.

## Свежесть и ручное обновление

При обычном остатке значок не показывается. Если хотя бы один лимит опускается до
**20% или ниже**, появляется `!` в цвете текста текущей темы (в Retro Pixel — белый).
Ниже **10%** он становится красным; при исчерпании — тоже красный.
Знак рисуется отдельной чёткой фигурой: пиксельной в ретро-темах и скруглённой в округлых. Точка появляется
только когда **оба** лимита полностью доступны (100%). Для этих значков нужны свежие
данные: старый кэш или округление 99.6% до 100% не должны создавать ложную точку.

По умолчанию значок находится справа в заголовке; при скрытом заголовке — возле
статуса активности. В панели он располагается возле логотипа. Во вкладке «Внешний вид»
можно выбрать расположение или скрыть значок, отдельно включить предупреждение и точку,
изменить порог появления и порог красного цвета от 0 до 100% и отключить приглушение устаревших данных. Настройки независимы
для каждого экземпляра; порог применяется к любому из двух окон квот.

Возраст каждого окна, обновление и ошибки остаются в общей подсказке виджета.
По умолчанию через три минуты без успешного обновления полоса приглушается. Ошибка
также приглушает сохранённые значения, но не обнуляет их и не меняет время успеха.

**ПКМ → Обновить лимиты** обновляет текущий сервис без ожидания минутного интервала.
Запрос выполняется в фоне; несколько экземпляров используют общую блокировку.
Повторные ручные запросы ограничены интервалом пять секунд. При выключенном
мониторинге или пользовательском скрипте действие недоступно. Скрипты без временных
меток работают как раньше, без индикатора; для его включения можно вернуть
`timestamp` или `bar1_updated_at` / `bar2_updated_at` в секундах Unix.

## Настройки

**Основные:** сервис, автоматический мониторинг, интервал активности (1–60 секунд),
необязательный пользовательский исполняемый скрипт с JSON на stdout.

**Внешний вид:** тема, заголовок, акцент, сегментированные или плавные полосы,
размер и анимация логотипа, десятые процента и таймеры сброса.

Доступны семь тем: Retro Pixel, Material 3 Expressive, Windows 95 Classic,
Cyberpunk 2077, Gruvbox Retro, Catppuccin Mocha и Tokyo Night.

## Проверка провайдеров

```bash
python3 contents/scripts/status_provider.py --provider antigravity
python3 contents/scripts/status_provider.py --provider codex
# Дождаться сетевого обновления кэша:
python3 contents/scripts/status_provider.py --provider codex --refresh-only
# Принудительное обновление (общая блокировка и пауза 5 секунд сохраняются):
python3 contents/scripts/status_provider.py --provider codex --refresh-only --force-refresh
python3 -m unittest discover -s tests -v
```

Обычный вызов немедленно возвращает кэш и при необходимости запускает фоновое обновление.
Пользовательский скрипт по-прежнему можно передать позиционным аргументом.

## Обновить скриншоты

Рендер использует настоящие QML-компоненты и фиксированные демонстрационные данные,
не запускает агентов и не обращается к аккаунтам. Нужен Python с PySide6:

```bash
python3 tools/render_screenshots.py
```
